# План рассказа

## ЧП1, около 7 минут

Слайды https://claude.ai/artifact/KBjc7DnToLvJQ7UV29C4xu, по одному пункту на слайд.

| Слайд | Время | Что сказать |
|---|---|---|
| 1. Обложка | 10 с | AR-02, протокол монтирования папки пользователя в песочницу агента. Тему взял в порядке исключения |
| 2. Задача | 40 с | Агент в удаленной песочнице, папка у пользователя, каждая файловая операция идет по сети. При RTT 200 мс наивный протокол обходит репозиторий из 2000 файлов около 9 минут. Клиент и сервер протокола и есть то, что растет на арене |
| 3. Гейты | 40 с | Быстро легко, если кэшировать все. Пять гейтов, главный это свежесть за 1 с. Одно нарушение на любом экземпляре обнуляет кандидата. TTL-кэш NFS этот гейт не проходит |
| 4. Домен | 40 с | Двенадцать классических подходов сводятся к трем выборам. Как узнавать об изменениях, что тянуть заранее, когда отправлять записи. Baseline это sshfs без кэша, классический ориентир это callback AFS, READDIRPLUS и файл целиком |
| 5. Симулятор | 40 с | Настоящая сеть стоила бы часы на кандидата. Симулятор с виртуальным временем, клиент и сервер в отдельных процессах шлют байты через модель TCP. Кандидат стоит минуту, сеть детерминирована, разброс 1-1,5% дает только CPU. Тесты ловят 9 жульнических и сломанных кандидатов |
| 6. Данные | 30 с | Деревья по статистике 64 репозиториев, 6 сценариев на 8 профилей сети. Split по деревьям, потому что экземпляры одного дерева делят пути. Погрешность public около 5% |
| 7. Метрика | 30 с | Среднее геометрическое ускорение относительно baseline. Времена экземпляров отличаются на порядки, поэтому не сумма. Метрика сверяет число операций и хеш итоговой папки |
| 8. Арена | 40 с | Исследователь меняет два файла и видит train, public отдает только балл, private ничего. Лимит 30 решений, из 4 финалистов private выбирает 2. Smoke пройден, кейс прогнан в контейнере runner арены |
| 9. Первые цифры | 30 с | Baseline 1,00, классика 1,74 на train и 1,76 на public. Обход ускоряется в 8 раз, записи и большой файл почти нет, там простор для эволюции |
| 10. Проверочная кампания | 50 с | Два исследователя на Opus, четыре решения. На v1 лучший дал 27 раз. Ревью нашло три особенности симулятора, которых нет в сети. Я закрыл их в v2, на v2 никто не прошел в финалисты |
| 11. Абляция | 50 с | Выигрыш r1 почти целиком дали общие часы, 22,5 раза с ними и 3,2 без них. Это аренда свежести, прием из настоящих систем, но в v1 часы совпадали точно. На v2 ее можно сделать честно, если оценить сдвиг часов как NTP. Это первый вопрос к основной кампании |
| 12. План | 20 с | К ЧП2 решение по нормировке CPU, подготовка и основная кампания на модели курса. К ЧП3 private, перепроверка на настоящей сети и навык |

Подробности для ответов в [evolution.md](evolution.md), [arena.md](arena.md) и ADR.

## Вопросы, к которым стоит быть готовым

| Вопрос | Короткий ответ |
|---|---|
| Почему не настоящая сеть | Часы на кандидата и шум. Симулятор дает минуту и разброс до 1%, а настоящую сеть я использую для перепроверки финалистов ([ADR-0001](adr/0001-virtual-time-simulator.md)) |
| Не переобучится ли эволюция на симулятор | Может. Поэтому финалистов проверяю на Linux с `tc netem` и FUSE и смотрю, сохраняется ли порядок |
| Почему среднее геометрическое | Времена экземпляров отличаются на порядки, сумма отдала бы весь вес медленным профилям ([ADR-0002](adr/0002-metric.md)) |
| Почему T = 1 с | Меньше нельзя проверить на RTT 200 мс, больше пользователь заметит. TTL-кэш NFS (3-60 с) этот гейт не проходит |
| Что мешает кандидату подделать отчет | Фиксированный `solve.py`, процессы spawn, проверка области изменений, сверка числа операций и хеша итоговой папки ([ADR-0005](adr/0005-isolation.md)) |
| Почему split по деревьям | Экземпляры одного дерева делят пути, иначе утечка из train в private ([ADR-0004](adr/0004-split.md)) |
| Что с моделью исследователей | Проверка шла на Opus, основная кампания пойдет на модели курса, private до нее не тронут ([ADR-0006](adr/0006-researcher-model.md)) |
| Где ML | Прогноз следующих обращений агента для предвыборки. Это аналог hoarding из Coda, эволюция может до него дойти, если ей это выгодно |
| Зачем проверочная кампания, если она не основная | Она нашла три дыры в симуляторе и генераторе. Без нее основная кампания потратила бы лимит на подгонку под них |
| Насколько стабилен балл | Сеть детерминирована сидом экземпляра. Шум дает процессорное время. У baseline и классики повтор меняет итог на 1-1,5%, у тяжелого по CPU кандидата до 11% при разной загрузке машины. Поэтому меряю при одинаковой параллельности, а до основной кампании решу про нормировку CPU ([ADR-0009](adr/0009-cpu-time.md)) |
| Кейс точно запустится в арене | Я прогнал solve.py в контейнере с параметрами runner арены (без сети, корень только для чтения, 2 ГБ, 2 CPU). Код выхода 0, ответ меньше 1 КБ, пик памяти 85 МБ ([results/checks](../results/checks)) |
| Зачем в арене разные роли | Каждая защищает от своей ошибки. Метрику замораживает агент подготовки до поиска, private держит оператор, лимит считает оркестратор, ревьюер ловит подгонку и выход за разрешенные файлы ([arena.md](arena.md)) |
| От чего защищает видимость split | Public отдает одно число, по нему не видно, какой экземпляр сломался. Private не возвращает ничего, поэтому финальная оценка не становится обратной связью для поиска |
| Почему лимит в решениях, а не в токенах | Лимит в тех же единицах, что ось кривой, и не зависит от модели. Упавшее решение тоже занимает место, иначе можно бесплатно пробовать |
| Как считается AUC | Точка встает по числу предложенных решений к концу проверки, значение держится до следующего события. В проверочной кампании AUC 26,6 на горизонте 4 |
| Где граница изоляции | Контейнер на каждый пример, без сети, кандидат и симулятор только для чтения. Отчет симулятора рождается рядом с кодом кандидата, поэтому подделку отчета ловят ревью диффа и два разрешенных файла, а не контейнер |
| Почему упали 4 теста арены | Это macOS. Длина пути ограничена 1024 байтами, APFS не принимает имена не в UTF-8, Compose из Docker Desktop иначе рендерит конфиг, и один тест переименовывает каталог в самого себя. Smoke прошел |
| Что если арена найдет новую дыру в v2 | Метрика заморожена на время кампании. Найденную дыру я фиксирую в разборе, а кандидата с ней не беру в финалисты по ревью |
