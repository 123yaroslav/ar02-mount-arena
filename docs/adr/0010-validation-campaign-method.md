# ADR-0010. Проверочная кампания без оркестратора арены

Статус accepted, дата 2026-11-06.

## Контекст

Проверочную кампанию нужно было провести до ЧП1, а код арены на моей машине на тот момент не запускался. Модели курса тоже еще не выдали ([ADR-0006](0006-researcher-model.md)).

## Решение

Кампания шла по методологии арены вручную. Отличия такие.

| Что | В арене | В проверочной кампании |
|---|---|---|
| Исследователи | агенты в worktree под оркестратором | два агента Claude Opus 5.5 в отдельных копиях репозитория |
| Оператор и ревьюер | отдельные роли | я сам |
| Журнал | SQLite `evaluator.search` | [journal.jsonl](../../results/validation-opus/journal.jsonl), одна запись на решение |
| Public | сервис оценщика, исследователь видит только балл | я считал `scripts/evaluate.py --quiet` и передавал исследователю только балл |
| Private | финализация K в N | не трогали |
| Кривая и AUC | `evaluator.search curve` | `scripts/curve.py` по тем же правилам, точка по числу предложений к концу проверки |
| Снимки кандидатов | `propose` с digest | каталоги в [candidates/](../../results/validation-opus/candidates), digest в `results/v2/<id>/train.summary.json` |

Направление метрики maximize. Ключ сопоставимости это версия симулятора и данных, v1 или v2, поля журнала `*_v1` и `*_v2` не смешиваются.

## Альтернативы

Подождать арену и модели курса. Тогда дыры симулятора нашлись бы уже в основной кампании, и часть лимита ушла бы на подгонку под них.

## Последствия

Журнал проверочной кампании не загружается в арену как есть. Основная кампания идет через `evaluator.search` и SQLite. Токены исследователей в проверочной кампании не записаны, поэтому ее нельзя сравнивать с основной по расходам.
